# Native session-key mining

This feature is stacked on the refactor in PR #12. `feat/session-keys` inherits `fix/separate-miner-staking-legacy` through ordinary merges (no history rewrite); its PR targets that branch, so shared wallet/staking fixes remain in PR #12. Merge the refactor first, then retarget this PR to `main` if needed.

## User flow

1. Open `/mining`, choose a compatible AploNode RPC, and connect the owner wallet.
2. Set the maximum GAPLO gas budget and lifetime (2–1,000 blocks; default 1 GAPLO/200 blocks).
3. Click **Authorize Mining** and confirm the direct registry transaction in the wallet.
4. Click **Start Mining**. If stake is below 1,000 APLO, the owner wallet confirms staking only the missing amount. The session then signs shares without wallet prompts.
5. Stop mining before clicking **Revoke Mining Access**. The owner confirms revocation, and the UI waits for its successful receipt and empty registry state.

Private session keys are generated with Web3’s cryptographic account generator and kept only in page memory. Public revocation metadata is saved by owner/chain after the registration hash is returned. Reload/navigation, changing RPC, or disconnecting/changing the wallet discards the private key. Reconnect to revoke the previous session before authorizing a new one. A confirmed absent/revoked/expired record can be cleared; an unconfirmed registration cannot be silently forgotten. Keys are never reused or extended.

## Protocol binding

Primary source: [AploNode native session keys](https://github.com/AploCoin/AploNode/blob/4d3d3f8c63fb314ec23d7369f687033cdf26ac93/docs/session-keys.md), merged in [AploNode PR #10](https://github.com/AploCoin/AploNode/pull/10).

- Registry: `0x0000000000000000000000000000000000001237`.
- Registration: `CreateSessionKey(key,target,selectors,aplo,gaplo,expiry,proof)` signed by the owner.
- Allowed target: GAplo `0x0000000000000000000000000000000000001234`.
- Only selector: `mine(bytes32)` / `0x2fdc505e`.
- Native APLO allowance: **zero**. Session scope does not include staking, approvals, transfers or registry mutation.
- Fee budget: user-entered GAPLO converted exactly to wei, positive and within uint256.
- Expiry: current head + selected block count; the sender verifies that the next block is still within the inclusive expiry.
- Proof: raw Keccak of `APLO_SESSION_KEYS_ACCEPT_V1 || registry[20] || chainId[32] || owner[20] || abi.encode(key,target,[mineSelector],0,budgetWei,expiry)`, signed by the session key with low-S and `v=0/1`. It is not a personal-message or typed-data signature.
- Session transactions: zero value, protected legacy transaction signed with the session key and its pending nonce. The owner pays gas and receives the protocol’s routed rewards.

The shared worker and mining loop hash the **session address**, and mining parameters are read for that address. Balance and stake are queried for the **owner**. `eth_call` reads use the owner as caller: a mining-only session is not authorized to call view selectors. Fresh session metadata uses the contract’s actual `DEFAULT_DIFFICULTY`, rather than the initial UI placeholder.

Before each share, the signer checks owner, target, zero native allowance, original expiry, current chain, remaining fee budget and exact calldata. It rechecks the maximum fee reservation immediately before signing. Revocation, expiry, budget exhaustion or an RPC verification error disables the sender and stops the mining loop; errors never trigger a direct-wallet mining fallback. Receipt polling normalizes Web3’s `TransactionNotFound` to “not confirmed yet,” while preserving real RPC/revert errors.

## Verification and limits

The test vector in `verification/session-proof-vector.json` was generated by AploNode’s `sessionkeys.ProofHash` and `crypto.Sign`; the TypeScript test compares both the hash and all 65 proof bytes. The native devnet smoke additionally submits the browser-generated proof to the actual registry, mines with the browser worker/session signer, and revokes through the owner wallet. `verification/native-session-smoke.json` records only public transaction hashes and addresses.

The current verification uses the binary built from exact AploNode commit
`934f90946472297f2fb1e063491132f66e4aee30` ([zero-sender eth_call fix, node PR #12](https://github.com/AploCoin/AploNode/pull/12)),
SHA-256 `bdd11458033d49c9efabdda708625c597c52d6895a5d104b27cda35ab545b3ef`.
It runs with a fresh disposable data directory, disabled peers/discovery and localhost HTTP.
The browser EIP-1193 adapter forwards owner transactions to the unlocked **local dev-only**
faucet. The browser worker, session signature, broadcast, registry and contract execution
are real. This is not a test of MetaMask or another installed wallet extension.

`e2e/native-balance.spec.ts` sends raw HTTP `eth_call` requests without the signing
adapter: `balanceOf(reportedOwner)` at both `0x1234`/`0x1235`, latest/genesis,
with omitted sender, zero sender and an unfunded nonzero sender. All 12 must return
uint256 on the fixed node. The preserved old binary was also tested with
`APLO_EXPECT_CALL_REVERT=1`: its eight omitted/zero-sender calls revert; its four
nonzero-sender calls succeed. The frontend does not patch these balance calls with
an artificial `from` or suppress their errors. This guard is independent of the
owner-caller used for native session registry/mining reads.

The lifecycle smoke checks initial zero stake → owner authorization → exactly
1,000 APLO stake → a session-signed share at the session nonce → successful receipt
→ actual fee deducted from the session budget → mining reward routed to owner,
with the session's own APLO/GAPLO balances unchanged at zero → stop/revoke.
It compares balances and budget at the share's exact block and its parent. The
negative native test verifies expiry (the registry hides expired records), explicit
revocation and a one-wei budget, with zero pending session nonce in each rejected
case. Fixture browser tests separately cover unsupported nodes, wallet refusals,
context changes, pending authorization, reload and public-only revocation metadata.

A budget below the 21,000-gas intrinsic floor is rejected before `estimateGas` so
that the node's allowance rejection does not become a generic contract error.
The complete maximum-fee check still runs immediately before signing.
Pending authorization/revocation stays locked across wallet context changes;
private keys are discarded and submitted public metadata remains recoverable.

Example reproduction using a locally built AploNode:

```bash
geth --datadir /tmp/webminer-native-dev --dev --dev.period 1 \
  --http --http.addr 127.0.0.1 --http.port 18545 --http.api eth,net,web3 \
  --http.corsdomain http://127.0.0.1:3219 --http.vhosts localhost,127.0.0.1 \
  --ipcdisable --nodiscover --maxpeers 0
```

In another terminal, after building WebMiner:

```bash
APLO_NATIVE_RPC=http://127.0.0.1:18545 \
APLO_NODE_REVISION=934f90946472297f2fb1e063491132f66e4aee30 \
APLO_NODE_BINARY=/path/to/aplo-geth-fixed npm run test:e2e -- --grep 'native AploNode'
```

`SAVE_NATIVE_EVIDENCE=1` refreshes the public receipt, raw balance RPC and negative-check records under `docs/verification/`; `CAPTURE_SCREENSHOTS=1` refreshes current/home interface captures and the native access/mining screenshots. Run against a fresh isolated chain when checking the missing-stake path.

Public nodes were not used for this verification. The local chain proves compatibility with the tested AploNode implementation; it does not establish that public nodes have deployed the native-genesis protocol. Existing networks without native registry state cannot gain support through a WebMiner change. No public-network transaction was sent, and no existing AploNode data directory was modified.
